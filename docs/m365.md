# m365 — agent CLI contract

Microsoft 365 CLI for one signed-in user. JSON on stdout by default.
Repo: `github.com/masonhuemmer/m365`. Binary: Homebrew `masonhuemmer/tap` (`m365`). Scoop: `masonhuemmer/scoop-bucket`. WinGet: `JacobHuemmer.m365` after the community PR merges.

## Contract

```
m365 <namespace> <verb> [flags]
```

- JSON default. `--human` for text. `--json` and `--human` together → 3.
- Results on stdout (one JSON value). Diagnostics on stderr.
- `chat` is an alias of `teams`. Canonical name: `teams`.
- `--help` exits 0 and does not need a session.
- Never print tokens, refresh tokens, codes, or client secrets.
- Attachment/file bytes never appear on stdout. Download/save write to `--out` only.

Exit classes: `0` success; `3` usage/config; `4` auth/consent; `5` service; `6` not-found.

Failure (JSON): one stderr object `{ "class": "usage"|"auth"|"service"|"not_found", "message", "hint"? }`.

List pages: `{ "limit", "count", "items", "next_page"? }`. Next page via `--page-token`, never a Graph URL. Max `--top` 50 (find/free have tighter max). Empty list → 0.

## Preflight

`m365 auth status` must show `signed_in: true` and `session_usable: true` plus the namespace you need under `namespaces`. If not, stop and tell the human to run `m365 auth login` in a terminal. Do not loop login. Do not call `auth login` or `auth logout` through MCP.

## Namespaces

| Namespace | Verbs |
| --- | --- |
| `auth` | `login`, `status`, `logout` |
| `mail` | `list`, `get`, `thread`, `watch`, `send`, `reply`, `attachments`, `save-attachment` |
| `teams` (`chat`) | `list`, `find`, `get`, `messages`, `send`, `watch`, `attachments`, `save-attachment` |
| `calendar` | `calendars`, `list`, `get`, `create`, `update`, `delete`, `free` |
| `files` | `root`, `list`, `get`, `download`, `upload`, `create-folder`, `delete`, `move` |
| `mcp` | `serve` |

Limits: `--top` default 10 (mail list, calendar list), 20 (teams list, calendars, files list); max 50. Attachments: 10 MiB/file, 10 files/send. Upload: 100 MiB.

Writes (`mail send`/`reply`, `teams send`, `calendar create`/`update`/`delete`, `files upload`/`create-folder`/`delete`/`move`): use `--dry-run` first. Dry-run JSON includes `dry_run: true` and does not mutate.

## MCP (`m365 mcp serve`)

Stdio JSON-RPC. Tools: `m365_status`, `m365_help`, `m365_run`. Recipes (help `topic` and prompts): `mail-search`, `teams-find`, `calendar`, `files`. Writes through `m365_run` dry-run unless `write_opt_in` is true. Do not use `--human`. Prefer MCP when connected; this file is the CLI contract MCP run executes.

## auth

| Command | Notes |
| --- | --- |
| `auth status` | `{ signed_in, session_usable, account?, namespaces: { mail, teams, calendar, files } }` |
| `auth login` | Interactive browser. Human terminal only. Missing `M365_CLIENT_ID`/`M365_TENANT_ID` → 3. |
| `auth logout` | Already signed out → 0. |

Config: `~/.config/m365/.env` (see `.env.example`) or those env names. Tokens in Keychain (file fallback `~/.local/state/m365/session.json` mode 0600). Experimental mail-classification policy is read from `~/.config/m365/config.json`; its TypeSafe credential is environment-only as `TYPESAFE_API_KEY` (alias `TYPESAFE_AI_TOKEN`).

## mail

| Command | Flags / args |
| --- | --- |
| `mail list` | `--folder` (inbox\|sentitems\|drafts\|all, default inbox) `--unread` `--search` `--top` `--page-token` |
| `mail get` | `MESSAGE_ID` — body as text; attachment metadata, no bytes |
| `mail thread` | `MESSAGE_ID` `--bodies` — oldest first; includes own replies |
| `mail watch` | `--folder` (default inbox) `--include-existing` `--classify` `--target-address` (repeat) `--target-name` (repeat) — JSON lines |
| `mail send` | `--to` (repeat) `--subject` `--body`/`--body-file` `--cc` `--attach` `--html` `--format md` `--dry-run` `--preview`. Always sent as HTML; plain text keeps paragraphs and line breaks. |
| `mail reply` | `MESSAGE_ID` `--body`/`--body-file` `--all` `--attach` `--html` `--format md` `--dry-run` `--preview` (default: sender only). Plain text keeps line breaks; the quoted thread stays below. |
| `mail attachments` | `MESSAGE_ID` |
| `mail save-attachment` | `MESSAGE_ID` `ATTACHMENT` `--out` `--overwrite` (refuse existing without overwrite) |

For `mail send`, `mail reply` and `teams send`: `--dry-run` JSON includes `rendered` (`content_type`, and `content`: the exact body that is sent) and `format_problems` (`rule`, `detail`). A real send with any format problem (disallowed tag or attribute, broken HTML, leftover markdown, literal `\n`, blank-line runs, non-http(s)/mailto link, markdown or a newline in the subject) fails with a usage error (exit 3) and sends nothing. `--preview` implies `--dry-run` and draws the message as text in a box, with problems listed below; it cannot be combined with `--json` and is refused over MCP. `--format` accepts only `md`, and not together with `--html`.

Search: `--folder all --search 'from:ajay'` or `subject:…`. `--body-file` may be `-` (stdin). Unknown folder or id → 6.

`mail reply --attach LOCAL_FILE` (repeatable, also with `--all`) sends local files alongside the authored reply comment. All files are read before the reply request; an unreadable file fails with exit 3 and sends nothing. Graph rejection returns its mapped error without a text-only fallback or success result. Dry-run and preview expose file names and sizes, never file bytes. The existing caps of 10 files and 10 MiB per file are local validation limits; Graph can reject a payload below those limits.

### Mail watch and response triage

`mail watch` performs one folder-scoped Microsoft Graph delta round and exits. It rejects folder `all`. With no checkpoint, the default first poll saves a quiet baseline; `--include-existing` instead emits existing changes. Later polls resume from the account-and-folder checkpoint in `$XDG_STATE_HOME/m365/mail-watch.json` or `~/.local/state/m365/mail-watch.json`. Output is JSON Lines, not one JSON array. A paging, classification, output, or checkpoint failure leaves the previous cursor in force, so a later invocation can repeat events.

Classifier-free lines use event `mail.changed` and contain only stable message/conversation identifiers, received time, subject, and sender. They do not contain bodies, attachments, Graph cursors, or revision values.

`--classify` additionally requires all of the following:

1. `experimental.mail_response_classification.enabled` is explicitly `true` in `config.json`. A token alone never enables it.
2. `TYPESAFE_API_KEY` (or its alias `TYPESAFE_AI_TOKEN`, used only when `TYPESAFE_API_KEY` is unset) is present in the process environment. It is not accepted as a CLI/MCP flag and is never persisted.
3. The target has at least one authoritative email address from the signed-in account or repeatable `--target-address`; repeatable `--target-name` values provide context only.

Default non-secret configuration:

```json
{
  "experimental": {
    "mail_response_classification": {
      "enabled": false,
      "provider": "jev",
      "model": "jev-latest",
      "actionable_threshold": 0.8
    }
  }
}
```

The live provider is TypeSafe Jev. Each changed conversation sends one Choice request containing at most the latest 10 chronological messages and 65,536 bytes of normalized body text. Participant addresses, received times, subjects, target identity, and truncation metadata may cross that boundary; attachments, attachment bytes, Graph cursors, revisions, and Microsoft/TypeSafe credentials do not. Provider requests have a 15-second timeout and no implicit retry. Provider HTTP, timeout, or response-validation failures are class `service`, expose no provider body/header/credential, and do not advance the mail checkpoint.

Classified lines use event `mail.response_classified` and include all four probabilities, `target_probability`, optional provider `confidence`, the returned versioned model, and threshold-derived `actionable`. Status is exactly one of `waiting_on_target`, `waiting_on_other`, `no_response_expected`, or `unclear`. No raw body appears in the event.

`actionable: true` is routing metadata, not permission to reply. The agent workflow is:

1. Read the cited conversation with `mail thread MESSAGE_ID --bodies`.
2. Compose reply text outside `m365`.
3. Preview with `mail reply MESSAGE_ID --body ... --dry-run`.
4. Ask for review/approval.
5. Send with a separate terminal command, or through `m365_run` only with `write_opt_in: true`.

Classification never drafts, creates Outlook Draft items, or sends mail. Through MCP, `mail watch --classify` stays a read/classify operation, while the later `mail reply` remains dry-run by default.

## teams (`chat`)

| Command | Flags / args |
| --- | --- |
| `teams list` | `--top` `--page-token` `--include-hidden` (chats hidden with `teams hide` are skipped by default) |
| `teams find` | `QUERY` `--group` `--top` (default 10, max 20). Person prefers 1:1. Never sends. Empty → 0. `incomplete: true` if scan ceiling (10×50) hit. |
| `teams get` | `CHAT_ID` — members included |
| `teams messages` | `CHAT_ID` `--top` `--page-token` `--include-system` |
| `teams send` | `CHAT_ID` **or** `--to QUERY`, plus `--text`/`--text-file` `--attach` `--html` `--format md` `--dry-run` `--preview`. Plain text keeps line breaks. Id and `--to` together → 3. Several find matches → do not send. |
| `teams watch` | `--since` `--chat` (repeat) `--top` — JSON lines, not one object |
| `teams attachments` | `CHAT_ID` `MESSAGE_ID` |
| `teams save-attachment` | `CHAT_ID` `MESSAGE_ID` `ATTACHMENT` `--out` `--overwrite` |

Examples: `teams find Ajay`; `teams find --group NOC`; `teams send --to Ajay --text ping --dry-run`.

## calendar

Own calendars only. List window default now → +7d. Create duration default 30 minutes. Working hours 09:00–17:00 local; 30-minute grid.

| Command | Flags / args |
| --- | --- |
| `calendar calendars` | `--top` `--page-token` |
| `calendar list` | `--calendar` `--start` `--end` `--top` `--page-token` |
| `calendar get` | `EVENT_ID` |
| `calendar create` | `--subject` `--when 'tomorrow at 1:30 pm'` `--until` `--duration` `--calendar` `--attendee` `--location` `--body`/`--body-file` `--dry-run` (`--when` and `--start` together → 3) |
| `calendar update` | `EVENT_ID` plus optional create fields `--dry-run` |
| `calendar delete` | `EVENT_ID` `--dry-run` |
| `calendar free` | `--when` (default tomorrow; day phrase) `--duration` `--hours` `--calendar` `--top` (default 5, max 20). `--dry-run` → 3. Fully booked → count 0, exit 0. |

`--when` create needs a clock time (`tomorrow at 1:30 pm`, `today 9am`, `Friday at 9am`, `2026-09-18 13:30`). Free accepts a day only.

## MCP run

`m365_run`: `{ namespace, verb, args?, flags?, write_opt_in? }`. Flags are long names without dashes (`folder`, `dry-run`, `top`). Same JSON as the CLI. Forbidden: `auth login`, `auth logout`, namespace `mcp` → usage. `mail watch --classify` does not consume or imply `write_opt_in`; a later `mail reply` is a distinct call and remains a forced preview unless that call explicitly opts in.

Overnight NOC poller is not this repo; see `~/origin/dotfiles/docs/m365.md`.
